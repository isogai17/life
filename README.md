# 余白 — AI日記Webアプリ

スマートフォンで今日のコンディションを記録し、MarkdownとJSONをコピーしてChatGPTに渡せる日記アプリです。React / Vite製の静的サイトで、バックエンドやAPIキーは不要です。

## 使い方

1. 日付、睡眠時間、体調、気分を入力します。日付は端末の今日の日付、睡眠時間は0〜24時間・0.5時間刻みです。
2. 「気づき」「できたこと」を自由に書きます。この2項目は空欄でも使えます。
3. 「ChatGPT用にコピー」を押し、ChatGPTのチャットに貼り付けます。「コピーしました！」が表示されたらコピー成功です。
4. 履歴を残す場合は「日記を保存」を押します。同じ日付の記録は更新されます。

下書きは自動保存され、再読み込み後も復元されます。履歴では検索、編集、コピー、削除、JSONの書き出しができます。ブラウザがコピーを許可しない場合には、手動コピー用の画面を表示します。

日記と下書きは**この端末・ブラウザのlocalStorage**、睡眠画像の原本は**同じブラウザのIndexedDB**に保存します。従来の日記データはそのまま使えます。外部への自動送信、端末間の同期、ChatGPTへの自動蓄積は行いません。ブラウザデータの削除やシークレットモードによって記録が消える場合があるので、大切な日記は「画像付きバックアップ」で書き出して保管してください。保存容量が不足しても本文のコピー機能は使えます。

## 睡眠画像を添付する

「睡眠の記録を、そのまま」の「睡眠画像を追加する」から、睡眠アプリのスクリーンショットを選びます。1日3枚まで、PNG・JPEG・WebP形式、1枚10MB・4,000万画素以下に対応します。HEICはPNGやJPEGに変換してから選んでください。

- 文字やグラフの精度を保つため、画像を縮小・圧縮・再エンコードせず、選択したファイルの原本を保存します。
- 添付は下書きにも保存されます。履歴へ記録するには「日記を保存」を押します。
- 履歴を開くと、添付画像の拡大表示と「共有・保存」ができます。共有対応のスマートフォンでは共有画面を開き、非対応の場合は元の画像を書き出します。
- 「添付から外す」は入力中の下書きへの変更です。保存済みの日記に反映するには、同じ日付で「日記を保存」を押してください。
- 画像内の睡眠時間・睡眠効率などをアプリが自動読取・自動入力する機能はありません。日記の睡眠時間は従来どおり0.5時間単位で入力し、画像内の正確な分・秒やグラフは原本を参照します。

### ChatGPTに渡す

1. 「ChatGPT用にコピー」を押し、Project内のチャットへ本文を貼り付けます。
2. **睡眠画像もチャットに別途添付してから送信**します。文字のコピーには画像本体を含みません。
3. コピーしたMarkdownとJSONには、添付画像の枚数・ファイル名・形式・大きさなどを含みます。画像の数値を推測せず、添付した原本を参照する指示も付けています。

過去の画像は履歴の「共有・保存」、または拡大画面の「画像を保存」から取り出せます。スマートフォンの共有先にChatGPTが表示されない場合は、画像を保存してChatGPTの添付ボタンから選択してください。

### 画像付きバックアップと復元

履歴の「画像付きバックアップ」は、**保存済みの日記**と全添付画像をZIPにまとめます。入力中の下書きは含まないので、先に「日記を保存」してください。ZIPの中には `yohaku-backup.json` と原本の `images/` フォルダが入ります。通常の「JSONを書き出す」は本文と画像メタデータのみで、画像本体を含みません。

「バックアップを復元」からZIPを選ぶと、確認後に日記と画像を復元します。同じ日付だけをバックアップの内容に置き換え、それ以外の日付と入力中の下書きは残します。別の端末やブラウザに手動で移す場合にも使えます。画像が欠けているZIPは復元せず、既存の日記を維持します。バックアップは画像合計200MB・日記JSON 5MB以内、復元時はZIP全体205MB以内です。

週次・月次でChatGPTの情報源にする場合はZIPを解凍し、JSONと必要な画像を添付してください。画像と日記の対応は、画像のファイル名に含まれる記録日とIDで確認できます。

## 開発

Node.js 22.12以降（クラウド環境ではNode.js 24）を使用します。

```sh
cd /workspace/life
npm ci
npm run dev -- --port 5173 --strictPort
```

ビルド・テスト:

```sh
npm test
npm run build
```

本番成果物は `dist/` に生成されます。日本語フォントも同梱しており、フォント配信サービスへの通信は不要です。フォントのライセンスは `public/font-licenses/` に含めています。

ブラウザテストはChromiumで、スマートフォンの画面・タッチ操作を再現します。

```sh
# 初回のみ、Playwrightのブラウザを用意
npx playwright install chromium
npm run test:e2e
```

このクラウド環境にはChromiumが導入済みです。追加ダウンロードなしで実行できます。

```sh
PLAYWRIGHT_CHROMIUM_EXECUTABLE_PATH=/usr/bin/chromium npm run test:e2e
```

コピーした実際のクリップボード内容、保存・復元・同日更新・削除・JSON出力、入力エラー、コピー権限や保存容量の不足、保存データの破損、画面幅320〜1440pxを検証します。画像のテストでは、原本ファイルと保存・ダウンロード・ZIP復元後のバイト列が一致すること、旧データの互換性、画像形式・容量・枚数の制限、画像保存失敗時にも本文を使えることを確認します。ブラウザテストは日記データを隔離した一時ブラウザで実行します。テスト画像は合成データで、ユーザーの睡眠画像をリポジトリに含めません。

## Vercelへのデプロイ

GitHubにコードをpushした後、Vercelでこのリポジトリをインポートし、以下を指定します。

| 設定             | 値              |
| ---------------- | --------------- |
| Framework Preset | Vite            |
| Install Command  | `npm ci`        |
| Build Command    | `npm run build` |
| Output Directory | `dist`          |

環境変数やAPIキーは必要ありません。Node.jsは24.xを使用します。`vercel.json` にビルド設定を同梱しています。VercelのHTTPSでクリップボードAPIを使用できます。

公開後は **Project → Deployments → 最新のProductionデプロイ → Visit** で本番URLを開きます。プロジェクトの **Settings → Domains** でも `https://（プロジェクトのドメイン）.vercel.app` を確認できます。そのURLをスマートフォンのSafariやChromeで開いてください。一般公開する場合は、**Settings → Deployment Protection** でProductionがVercelログインを要求しないことを確認し、ログインしていないブラウザでも動作を確認します。

CLIを使う場合は、PCのターミナルで以下を実行できます。

```sh
cd /path/to/life
npx vercel login
npx vercel --prod
```

初回のセットアップで自分のアカウント（またはチーム）を選び、このディレクトリを新規プロジェクトとして登録します。GitHub連携による自動デプロイも使う場合は、Vercelの **Project → Settings → Git → Connect Git Repository** からPush先のリポジトリを接続してください。CLIのログイン情報やアクセストークンをGitやチャットに記載しないでください。

## GitHub Pagesへのデプロイ

`.github/workflows/deploy-pages.yml` を同梱しています。

1. コードをGitHubの `main` ブランチにpushします。
2. リポジトリの **Settings → Pages → Source** を **GitHub Actions** に設定します。
3. Actionsの **Deploy to GitHub Pages → Run workflow** を実行します。更新時もこの操作で再デプロイします。Vercelを利用する場合にGitHub Pagesへ同時公開されないよう、Pagesの公開は手動実行にしています。

Viteの `base: './'` により、リポジトリ名を含むサブパスでも動作します。画面切り替えにサーバーのルーティングは必要ありません。GitHub PagesのHTTPSでコピー機能を使用できます。

## コピー形式

````markdown
【日記データ記録】

- 日付: 2026-10-14
- 睡眠時間: 7.5時間
- 体調: 4/5
- 気分: 5/5
- 気づき: 散歩で気分がすっきりした。
- できたこと: 本を読めた。

```json
{
  "date": "2026-10-14",
  "sleep": 7.5,
  "condition": 4,
  "mood": 5,
  "insights": "散歩で気分がすっきりした。",
  "achievements": "本を読めた。"
}
```
````

改行や引用符もJSONとして正しくエスケープします。自由記述にバッククォートが含まれる場合は、JSONのコードフェンスを安全な長さに調整します。
